<objective>
Add `update_experiment(record, store_dir, *, expected_base=None) -> Path`
to `experiment_store.py`: the single in-place overwrite write path that all three
Phase 13 commands funnel through (D-03). This closes CR-01 (the `log_experiment`
dedup-skip data-loss bug) by giving outcome-mutating writes a path that
intentionally OVERWRITES rather than early-returning on `dest.exists()`. Also
sweep WR-04: replace the D-13 leaf-name guard with an EQUAL expected_base check
(`store_dir.resolve() == expected_base.resolve()`), applied to BOTH the new
`update_experiment` and `log_experiment`.

Purpose: First-class, non-lossy "correct a logged eval" — the structural fix for
CR-01, not a bolt-on `--force` flag. This is the foundation the CLI commands
(13-04/13-05) write through. The `expected_base` parameter (Claude's Discretion on
the guard signature per CONTEXT) keeps the store module Click-free: the canonical
base is read from the store's OWN `EXPERIMENTS_DIR` constant (NOT imported from
cli.py) or passed in by the caller. `expected_base` defaults to `None` and resolves
to `EXPERIMENTS_DIR` INSIDE the body (read at call time, never bound at def-time) so
a monkeypatch of `experiment_store.EXPERIMENTS_DIR` is honored — the guard is jointly
satisfiable across the entire 13-01 test matrix (accept store_dir==expected_base,
reject store_dir!=expected_base, plus the production default-base path).
Output: `EXPERIMENTS_DIR` module constant, `update_experiment()` (new), and the
tightened EQUAL base guard in `log_experiment` and `update_experiment`. Turns the
Task-1 RED store tests from 13-01 GREEN. No schema change.
</objective>
