## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| untrusted `<id>` / `--from` / `--reviewer-model` → filesystem & model | A pasted model reply (e.g. Grok) and a user-supplied id are untrusted input crossing into load + persistence |
| CLI command → store write path | All outcome mutations must funnel through `update_experiment` (single write path), never a direct CLI file write |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-ERR | Tampering (untrusted input) | `--from` JSON, missing record_kind, partial flags | mitigate | WR-03 wraps `json.loads` → friendly ClickException (no traceback); WR-02 default-injects `record_kind` / friendly error; WR-01 raises a clear error instead of silent fall-through; `_read_critique_input` never `eval`/`exec`s pasted text |
| T-13-TRAV | Tampering (path traversal) | load-by-id for review/lessons | mitigate | `_load_experiment` (cli.py:108-110) resolved-parent guard reused verbatim — a crafted id cannot escape the store |
| T-13-CR01 | Tampering (data loss) | review/lessons writes | mitigate | `_mutate_experiment` routes through `update_experiment` (no dedup-skip); re-review replaces cleanly, no half-write |
| T-13-PRIV | Information disclosure (privacy boundary) | new free-text fields | accept | `experiment_scrub.py` already scrubs `reviewer_critique` + `lessons_learned` at the SHARE boundary (Phase 12); raw-at-rest is intentional (AR-11-01). NO scrub added to the write path |
| T-13-VOCAB | Tampering (invalid verdict) | `--action` | mitigate | `click.Choice(RECOMMENDED_ACTIONS)` rejects out-of-vocab at the CLI boundary; `update_experiment` re-validates as defense in depth |
| T-13-SCH | Tampering (schema drift) | schema freeze | mitigate | `git diff --quiet src/kajiba/schema.py` in verify; only existing optional fields written |
</threat_model>
