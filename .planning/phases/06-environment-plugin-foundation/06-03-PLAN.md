## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Hermes host → plugin register(ctx) | Untrusted plugin host calls into Kajiba code; Kajiba must never crash the host |
| Hermes hook payloads → handler kwargs | Raw session content (prompts/responses) crosses into Kajiba via hook kwargs — contains PII before any scrub |
| Symlinked plugin dir → code execution | Hermes loads/executes code from ~/.hermes/plugins/kajiba (a symlink into the repo) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-06 | Denial of Service | register(ctx) / handlers crashing Hermes | mitigate | register(ctx) and every handler wrap their body in try/except Exception + logger.exception and never raise into Hermes (CLAUDE.md fault-tolerance rule, MP-1/MP-2) |
| T-06-07 | Information Disclosure | KAJIBA_DEBUG logging hook kwargs (raw prompts/responses with PII) to logs before the scrubber runs | mitigate | _log_kwargs truncates every value to repr[:120] and logs type+name primarily; debug mode is opt-in (KAJIBA_DEBUG=1) and OFF by default; setup guide (Plan 04) warns that debug logs may contain unscrubbed content and should not be shared. Full message bodies are never logged. |
| T-06-08 | Elevation of Privilege / Tampering | Hermes executing arbitrary code from the symlinked plugin dir | accept | Local-first single-operator model: the symlink points into the developer's own repo (src/kajiba/plugin), which is already trusted code the developer wrote. No third-party plugin loading in scope. Documented as a dev-only symlink in the guide. |
| T-06-SC | Tampering | npm/pip/cargo installs | N/A | No registry package installs in this phase (06-RESEARCH Package Legitimacy Audit: none new) |
